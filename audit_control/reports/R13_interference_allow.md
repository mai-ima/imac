## 3. 'touch'(AABB最小重なり<0.15mm)の妥当性

| 観点 | 評価 | 根拠 |
|---|---|---|
| 数学的な安全性 | **上限としては妥当**。2物体の交差領域は全て AABB の重なりスラブ内に収まるため、最小軸の重なりは「貫入厚さの上限」。これが0.15mm未満なら、貫入は最大でも0.15mm | `interference_report.py:39` |
| 0.15mm の根拠 | **根拠なし**。コード・台帳・docs のどこにも記載が無い(`grep "0.15mm"` は docstring と生成MDの2箇所のみ)。BVH許容誤差 `epsilon=1e-4`(`build_imac_pc_v8.py:864`)との関係や、製造公差との対応も無い | grep結果 |
| 分布 | touch 371対のうち 362 対は深さ 0.000(AABBが面で接するだけ=面接触)、9対が 0.003〜0.1mm | 私の再実行 |
| 閾値近傍の恣意性 | riser×riser_plug の深さ 0.161mm(6対)は閾値を0.011mm超えて ALLOW 側。閾値が0.2なら不要になる規則。閾値と規則が整合していない | 私の再実行 |
| 0.003〜0.1mm の9対 | cam_roller0/1×hinge_cam_plate0/1(0.003、接触)/ cable_plug_W2_board×io_shield(0.1) / hang_pin0〜3_head×hexsocket(0.1) / tray_screw0/1×hex(0.05)。W2プラグ×シールドの 0.1 は実貫入。同じ eps8 周辺で eps8×io_shield は0.4で要対処に出るのに W2プラグは接触扱いと非対称 | 同上 |
| 見逃しリスク1: 薄物の完全内包 | 厚さ<0.15mmの部品は、何mm貫入・埋没していても「接触」に分類される。該当: ssd_slit(0.08)、hexsocket/hex(0.05〜0.1)、ラベル/文字(ext 0.08)。**ヘックスソケットは凹みではなく厚み0.05〜0.1mmの板を頭の上に載せた装飾**(`hardware_v8.py:31`: `icyl(..., .4, ...)` 等) | 私の再実行+コード |
| 見逃しリスク2: 細長部品の貫通 | 最小軸=貫通方向に薄い軸で判定される。細長い棒(例: Ø2のドエルピン `dowel_pin`、長いスペーサ、ケーブル)が板を貫通しても、棒の太さ軸の重なりが小さいため最小軸は「棒の太さ以下」。棒の太さ<0.15mm のケースは現状無いが、**最小軸は貫通深さではなく部品の厚さを測る場合がある**ので「深さ」の語は不正確。大きい値は大きい貫入を意味するが、小さい値でも十分長い貫通を示す可能性がある(厚みの薄い板×長い棒の組合せ) | 論理的指摘 |
| 見逃しリスク3: 傾斜部品 | 傾斜した部品(スポーク30°、羽根)のAABBは実形状より大きく、重なりを**過大評価**(安全側)。見逃しではなく過検出側 | 論理的指摘 |
| 推奨 | (a) 閾値の根拠を台帳に(製造公差・面取り量・モデル分解能)。(b) 「深さ」ではなく実貫入(頂点→相手面の符号付き距離)を記録。(c) touch 側の対も名前と深さを JSON に保存。(d) 厚さ<閾値の部品に貫入が無いことを別途確認 | |

## 7. 監査の限界(正直な注記)

- 実コネクタの嵌合深さ・規格寸法の数値(ATX24約9〜10mm、ファンヘッダ約5〜6mm等)は私の知識による**仮説**で、一次資料では確認していない。
- 点内外判定(完全内包の探索)は偽陽性が多く、確定した検出漏れの実例としては使えない。L1の具体例は「構造上検出できない」という論理的指摘であり、実際に埋没しているかは未検証(UNVERIFIED)。
- 頂点の「内側」判定(近傍面の法線符号)は開いた殻や非多様体で信頼できないため、深さの根拠には AABB 重なりと BVH 結果のみを使い、頂点判定は補助(傾向確認)にとどめた。
- `cable_H1/H2` がホースであるかは名前からの推定(仮説)。
